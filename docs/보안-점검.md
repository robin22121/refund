## 1. 개인정보 저장과 암호화

| 상태 | 항목 | 내용 |
|---|---|---|
| ✅ | 저장 암호화 | 접수 건 전체(이름·연락처·생년월일·수집 자료·서명)를 AES-256-GCM으로 암호화해 저장. 건 id를 AAD로 묶어 다른 건 암호문을 끼워 넣으면 복호화가 실패합니다. 키는 `DATA_ENCRYPTION_KEY`. |
| ✅ | 운영 키 강제 | `APP_ENV=production`에서 암호화 키가 없으면 서버가 뜨지 않습니다. 개발에서만 임시 키를 씁니다. |
| ✅ | 주민등록번호 도구 | 지금은 주민번호를 받지 않습니다(생년월일 6자리만). 경정청구서에 필요해지면 세무사 단계에서만 받고, 형식 확인·마스킹(`650302-1******`) 함수를 `security.py`에 두었습니다. 저장은 위 암호화로 덮입니다. |
| ⚠️ | 주민번호 처리 근거 | 개인정보보호법 제24조의2: 법령 근거가 있어야 처리 가능. 세무사의 경정청구 대리(세무사법·국세기본법 서식)를 근거로 삼고, 동의서에 고유식별정보 항목을 따로 받습니다. 위임 항목 4번이 이 동의입니다. 문구는 법무 검토가 필요합니다. |
| ⚠️ | 키 관리 | 운영에서는 KMS(AWS KMS·NCP KMS)에서 키를 받아 넣고, 키 교체 절차(`v1:` 접두사로 버전 구분)를 정해야 합니다. |
| ⚠️ | DB 전환 | 지금은 메모리 저장소라 재시작하면 자료가 사라집니다. DB로 옮길 때도 암호문 그대로 저장하고, 검색용 값만 해시 컬럼을 둡니다. |
| 📝 | 보관·파기 | 정산이 끝나거나 불인용된 뒤 보관 기간(세무사 업무 기록 보존 기간 확인)이 지나면 파기하는 작업이 필요합니다. |
| 📝 | AI 전송 | Claude에는 이름·연락처·생년월일을 보내지 않고 출생연도만 보냅니다. 주소와 신고 내역은 보내므로 처리방침에 국외 이전(Anthropic, 미국) 항목을 넣어야 합니다. |

## 2. 고객 API 접근 통제

| 상태 | 항목 | 내용 |
|---|---|---|
| ✅ | 접수 건 열람 | 전에는 건 id만 알면 누구나 `GET /cases/{id}`로 원자료·서명·세무사 내부 메모까지 볼 수 있었습니다. 이제 접수할 때 한 번 주는 토큰(`X-Case-Token`)이 맞아야 열리고, 서버에는 토큰 해시만 저장합니다. 화면은 이 탭의 sessionStorage에만 토큰을 둡니다. |
| ✅ | 고객에게 보이는 범위 | 고객 응답에서 수집 원자료, AI 초안, 세무사 검토·내부 메모, 인증 세션 id, 서명 이미지를 뺐습니다. |
| ✅ | 진단 직접 입력 API | `POST /diagnosis`는 세무사 키가 있어야 합니다. |
| ✅ | 보안 헤더 | CSP(외부 스크립트·프레임 금지), X-Frame-Options, nosniff, Referrer 차단, API 응답 캐시 금지, 운영 HSTS. |
| ⚠️ | 요청 제한 | 접수·주소 검색·간편인증 요청에 IP별 요청 제한이 없습니다. 간편인증 요청은 문자·알림 비용이 드니 출시 전에 게이트웨이나 미들웨어에서 막아야 합니다. |
| ⚠️ | 본인 확인 | 접수는 이름·생년월일·휴대폰만으로 됩니다. 실제 자료는 간편인증 승인 후에만 오지만, 그 전에 소재지로 등기부를 조회합니다. 등기부는 공개 자료라 위험은 낮지만 소유자 이름 일치 결과는 인증 뒤에 보여 주는 편이 낫습니다. |

## 3. 전자위임장

| 상태 | 항목 | 내용 |
|---|---|---|
| ✅ | 위임 내용 고정 | 서명할 때 수임 세무사(이름·등록번호), 위임 항목, 서명 시각, 서명 이미지 해시를 묶은 SHA-256(`document_hash`)과 서명 IP를 남깁니다. 나중에 위임 내용이 바뀌지 않았음을 보일 수 있습니다. |
| ✅ | 서명 이미지 검증 | PNG·JPEG data URL만, 약 300KB까지 받습니다. 전에는 아무 문자열이나 크기 제한 없이 받았습니다. |
| ✅ | 재서명 제한 | 간편인증을 시작한 뒤에는 위임장을 다시 쓸 수 없습니다. |
| ✅ | 응답에서 서명 제외 | 서명 이미지는 고객·세무사 API 어디에도 내려가지 않습니다(저장소에만 암호화). |
| ⚠️ | 법적 효력 | 그림 서명만으로는 본인 서명임을 증명하기 약합니다. 간편인증 승인을 위임장 서명 단계에서 받거나(전자서명법상 전자서명), 홈택스 세무대리 수임 동의 절차와 연결해야 합니다. 세무사회 수임 규정도 확인이 필요합니다. |

## 4. 세무사 검토실 인증

| 상태 | 항목 | 내용 |
|---|---|---|
| ✅ | 기본 키 차단 | `APP_ENV=production`에서 `demo-advisor`나 32자 미만 키를 쓰면 서버가 뜨지 않습니다. |
| ✅ | 대입 공격 | 같은 IP에서 10분에 10번 틀리면 잠깁니다(429). |
| ✅ | 접속 기록 | 목록 조회, 건 열람, 초안 재생성, 검토 저장, 제출, 결과 기록, 키 실패를 시각·행위자·IP와 함께 남깁니다 (개인정보의 안전성 확보조치 기준 제8조). 지금은 메모리와 로그입니다. |
| ⚠️ | 세무사별 계정 | 키 하나를 모든 세무사가 나눠 쓰는 구조라 누가 무엇을 했는지 구분이 안 되고, 퇴사자 회수가 어렵습니다. 세무사별 계정 + 2단계 인증 + 담당 건만 보이게 하는 권한이 출시 전 필수입니다. |
| ⚠️ | 키 저장 위치 | 검토실 화면은 키를 브라우저 localStorage에 둡니다. 계정 로그인으로 바꿀 때 HttpOnly 세션 쿠키로 옮깁니다. |
| 📝 | 접속 기록 보관 | 1년 이상(정보주체 5만 명 이상이면 2년) 위변조 방지 저장소에 보관하고 월 1회 점검합니다. |

## 5. 외부 연동

| 상태 | 항목 | 내용 |
|---|---|---|
| ⚠️ | 하이픈 암호화 IV | `encrypt_field`가 IV를 16바이트 0으로 둡니다. 하이픈 명세 확인 후 정해진 IV 규칙으로 바꿔야 합니다. |
| ⚠️ | 비밀값 | 하이픈·Anthropic 키를 `.env`에 둡니다. 운영은 비밀 관리 서비스로 옮기고 저장소에 올리지 않습니다(`.gitignore` 확인됨). |
| 📝 | 결제 | 지금은 가짜 PG입니다. 실제 PG 연동 때 결제 금액을 서버에서 다시 계산(이미 그렇게 함)하고 웹훅 서명을 확인합니다. |
